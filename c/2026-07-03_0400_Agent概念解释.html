关于概念混淆：Cron job 不是"生成一个常驻 Agent"——它只是按时间表启动一次性的 Agent 会话，跑完就销毁。

``
不是：┌─────────────┐
│ Agent 一直活着 │ ← 7×24 常驻
│ 每分钟自己查 │
└─────────────┘

而是：每分钟 → 点火 → Agent 会话启动 → 干完活 → 熄火 → 消失
`

Job A（no_agent`）连 Agent 都不启动，就是个 shell 脚本定时执行。Job B 才启动 Agent 会话。两个本质都是 cron 记录，不是独立运行的 agent 进程。

🤖 Hermes (04:05)
在 Hermes 里，Agent 不是"一个活着的进程"——它是一个"推理循环"。

核心代码在 run_agent.py，逻辑极其简单：

``
接收一条消息
→ 构建 system prompt（SOUL.md + 环境信息 + 工具列表 + 记忆）
→ 循环（最多 90 轮）：
→ 调 LLM API，把消息+工具发给模型
→ 模型返回"我要调终端" → 执行工具 → 把结果追加回对话 → 继续循环
→ 模型返回"我说完了" → 返回最终回答
→ Agent 结束，整个会话对象销毁
`

Agent = 一次"接收输入 → 调用工具 → 输出结果"的完整推理过程。 它没有心跳、没有后台常驻、没有自己的进程 ID。每次跟你聊天，都是启动一个新的 Agent 会话。

#### 同一个 Agent，四种用法

同一个 AIAgent 类，在不同场景下被启动：

| 场景 | 谁来点火 | 生命周期 | 记忆/上下文 |
|------|----------|----------|------------|
| CLI 对话 | 你敲 hermes 回车 | 你发一句 → Agent 处理 → 等下一句（session 持久化） | 有记忆、有 session 历史 |
| Gateway（QQ） | 你发一条 QQ 消息 | 消息到达 → Agent 启动 → 处理完 → 线程挂起等下一句 | 同上 |
| Cron Job | 调度器到点触发 | 到点 → Agent 启动 → 跑完 prompt → 输出结果 → 彻底消亡 | 无记忆（skip_memory=True） |
| delegate_task | Hermes 调用 delegate_task() | 下令 → 子 Agent 启动 → 干完活 → 返回摘要 → 消亡 | 无记忆、无历史、只能看到传的 context |

#### 回到 Twitter 方案里的"Agent"

Job B 本质上就是 Cron Agent：

`
每分钟 7:30:00 → 调度器点火
↓
AIAgent 实例诞生
→ 读 trigger 文件
→ 发现是空的 → 直接返回"无新推文"
↓
实例销毁（这一分钟的生命结束）

每分钟 7:31:00 → 又一个新的 AIAgent 实例诞生
→ 读 trigger 文件
→ 有内容！→ LLM 分析 → 飞书推送 → 删 trigger
↓
实例销毁
`

每分钟都是一个全新的 Agent，彼此不认识。它们之间唯一的通信方式是显式设计的外部状态（trigger 文件、上次 ID 记录等）。

关键结论：
- "生成一个 Agent"这个说法不够准确——Agent 不是长命的"进程"或"服务"，它就是一个按需点火、用完即灭的推理循环
- Job A（no_agent`）连点火都不跳过 Agent 循环，直接跑脚本
- 我们至今只有一个 cron job（天气），它每天点火一次，一次跑不到 10 秒就灭了

``

│ 加载记忆、工具 │
│ 调 LLM → 回答 │
│ 把本轮对话写回 │
│ SQLite │
└──────────────────┘
│
▼
Agent 实例销毁 ← 消亡

... 你思考中 ...

下一条 QQ 消息到达
│
▼
┌──────────────────┐
│ 又一个新 AIAgent │ ← 又一个全新实例
│ 从 SQLite 加载 │
│ 对话历史（含上一轮）│
│ ... │
└──────────────────┘
`

#### 对比表

| 概念 | 生命周期 | 本质 |
|------|----------|------|
| AIAgent 实例 | 单次 turn（你发一句 → 处理完 → 销毁） | Python 对象，瞬时的 |
| Session | 跨 turn（从第一条消息到 /new 或自然结束） | SQLite 里的对话历史记录 |
| Memory | 跨 session（持久化在 ~/.hermes/` 里） | 你的偏好、环境信息等 |
| SOUL.md | 跨一切（每次 Agent 实例诞生时重新读取） | 文件，修改即时生效 |

每次对话已经有多个 Agent 实例诞生又消亡——用户每发一句，Gateway 就 new 一个新的。但因为是连续的，每个新 Agent 实例都从 SQLite 里加载了之前的完整对话历史 + 从 Memory 加载了关于用户的记忆。所以它"知道"之前聊了什么。

Agent 是容器，Session 是容器里的水。 每轮换一个新杯子，但把同一壶水倒进去——喝起来是一样的。
